## Commands (run from `agent/`)
- Run live: `uv run --env-file ../.env python main.py` (needs `FIVEU_API_KEY` from the kit card and the backend on `BACKEND_URL`, default http://localhost:8000)
- Run local: `MOCK=1 uv run --env-file ../.env python main.py` (mails from `fixtures/inbox/`, nothing is sent; the LLM still needs the key from `.env`; sessions go to `BACKEND_URL`, so use a local backend, not the live one)
- Setup once: fill in `FIVEU_API_KEY` and `GATEWAY_OPENAI_KEY` in the root `.env`, then `uv run --env-file ../.env python setup_5u.py` (checks the team key, stores the OpenAI key in the gateway, lists allowed models, shows the raw mail fields)
- Test: `uv run pytest -q` · single test: `uv run pytest -q test_agent_core.py::test_route`

## Files
- `setup_5u.py`: one-time setup + health check for the 5U APIs.
- `main.py`: worker loop: fetch → route → RFQ / reply / tracking each in their own thread. A mail whose dispatch fails (e.g. backend down for a moment) is retried every poll for up to 5 minutes. Live mode: only one worker per machine (file lock in the temp dir, `WORKER_LOCK_FILE`), and RFQs older than 6 minutes are skipped (they can't score; protects a fresh `.since_id` from answering the backlog). A new customer mail that also asks where a BK- booking is gets the quote first, then the tracking answer (`RFQ_TRACKING`). On start (live) it resumes RFQs that were being priced when it stopped (`resume_unfinished`: stage new/pricing, no quote, ≥ 30 s of the 6 minutes left; the mail is fetched again by id).
- `llm.py`: the only gateway caller (5U gateway `/v1/gateway`, team key). `chat_json()` returns (data, cost_usd) and logs every call.
- `inbox.py`: mailbox adapters (`fetch` / `reply` / `send` / `attachment`). `FiveUMailbox` = the live 5U mailbox (thread = first mail's id, `in_reply_to` for replies, last seen id kept in `.since_id`); `FixtureMailbox` for tests and local runs.
- `router.py`: rules-first `route(mail, carriers, known_thread)`. No LLM.
- `airports.py`: codes we can price (kit carrier list, sheets, portal ports, zones). City names become codes after the extraction; when the extracted code gets no price, `aliased()` gives the same city's airport our lanes fly (HND → NRT, EWR → JFK) and the RFQ agent prices that. `AIRPORT_ALIASES=off` disables it.
- `extract.py`: the one LLM call per RFQ (copies numbers + units); `to_rfq()` converts to cm/kg in code and lists what's missing.
- `rfq_agent.py`: extract → mail carriers → collect bids until the cut-off (`BID_CUTOFF_SECONDS`, default 90 s after the RFQ) → `POST /api/price` with the bids → quote in the customer's thread → session events.
- `booking_agent.py`: customer reply → accept / decline / question (rules; LLM only if unclear or a question) → `POST /api/book` → booking mail in the thread. Also handles the airline's "Booking BK-… confirmed" mail. Booking traps (`test_traps2_booking.py`): DG papers alone never book (thanks + asks for the go-ahead); a yes from outside the customer's address/company domain asks the original contact; a cancel after booking gets an ack (no amount) + person; `CONFIRM_SENDER` (default on): a confirmation counts only from the booked airline's address and only once; two pending email bookings with one airline are matched by S-ref or request thread, else a person.
- `tracking_agent.py`: `tracking@` questions → find the booking by reference → answer from the CRM (no LLM). `tracking_match.py` finds it when the reference is missing or mistyped; switches (default on, `off` = before): `TRACKING_FUZZY` (bk-/PO spellings, rate ID, one BK typo only with a second signal: sender, thread, name, weight or lane), `TRACKING_FORMATS` (1.233,00 kg, 25.11.2026, city names, umlauts), `TRACKING_CUSTOMER` (company/contact name only; never another customer), `TRACKING_IN_THREAD` (status question in the booked thread). `test_tracking_sweep.py` holds ~120 phrasings.
- `follow_up.py`: `FOLLOW_UP` (default **off**, `on` to enable): one reminder without an amount ("shall I go ahead and book <airline>?") 150 s after a quote with no answer; never after any customer mail, a person, a gate hold, a DG or fallback quote; sent flag `quote.follow_up_sent_at` survives restarts. A yes books through `booking_agent`. Worker sweeps in its own thread.
- `bids.py`: `parse_bid` (regex, free) → `read_bid` (LLM only if the regex fails); `BidBoard` hands carrier replies to the waiting RFQ thread.
- `carriers.py`: carrier list (`CARRIERS_FILE`, default `fixtures/carriers.json`, our own format until the start-kit list arrives) and who to ask per RFQ.
- `templates.py`: customer quote (one all-in amount) and carrier bid request (asks for a reply format the regex reads). Placeholder wording until U4.
- `backend.py`: HTTP client for the backend contract.
- `gate.py`: quote gate, the last free check before every quote (rules, no LLM): special cargo (DG beyond dg.py, temperature, perishable, valuables, oversize, live animals), arrival deadline and budget next to the ask, door-to-port without a pickup leg, a total far below the others, other currency, prompt injection, one amount per mail; a calendar week deadline ("KW 49", `WEEK_DEADLINE`) is that ISO week's Friday; laptops / cordless tools / phones get one sentence asking for the battery details, never DG papers (`BATTERY_GOODS`). fix = we change the quote, hold = flag + ntfy, auto-send at `GATE_AUTO_SEND_SECONDS` (240) unless a person pauses or quotes. `GATE_MODE=enforce|warn|off`.
- `amendments.py`: customer mails that arrive in the thread before our quote; the RFQ agent reads the request again with them before quoting (also a correction in the same poll as its RFQ, `EARLY_CORRECTION`; keeps ruled-out airlines, `CORRECTION_KEEPS`; drops bids asked for the old figures, `CORRECTION_BIDS`); a correction while the gate holds the quote is read too, and the re-read keeps attachment texts such as a voice memo transcript.
- `units.py`: `UNIT_GROUNDING`: the unit, "each"/"total" and decimal split the mail writes next to each number the model returned (lbs/in/t read as kg/cm, "1.234,5" read as 1.2345). Rules, no LLM. `UNIT_ASK` (default on, in rfq_agent): a weight, dims triple or volume the mail (subject, body, attachments) writes with no unit anywhere → one question in the customer's language, no amount ("715: kg / lbs?"), `rfq.awaiting = "units"`; the answer is read by rules (`units.answered`) and quoted once in the same session (`resume_after_units`).
- `shapes.py`: RFQ shapes one all-in amount must react to, rules only: several shipments → lot 1 quoted alone with one sentence for the rest ("one total for both" over two lanes: a person, no quote), or the reading as is when lot 1 can't be isolated (`MULTI_SHIPMENT=quote`, default; `hold` = a person, no quote; `off` = main), sentences about earlier or later orders never count, EXW/FCA at a German site → door-to-port (`INCOTERM_PICKUP`), DDP/DAP/door delivery → "not included" sentence (`DESTINATION_DELIVERY`), cheapest AND fastest → the other option named in words (`BOTH_ASKS`).
- `cloud_links.py`: `CLOUD_LINKS`: next to links.py (which reads every link): a request only behind a Dropbox / Drive / OneDrive / SharePoint / Box / WeTransfer link that can't be read gets the written details ask ("I can't open the link you shared"); "upload the quote to our Drive" → quote in the body and as the offer file, one line saying we can't upload. links.py also rewrites OneDrive/SharePoint shares to download=1.
- `requote.py`: `REQUOTE` (rfq_agent.requote_after_change): the customer changes the shipment after our quote (R86/R87). A change word + a new weight that differs from the quote → re-read, re-priced with the same objective and constraints, one new amount, the session quote replaced (a "yes" books the new rate). New pieces / volume / dims without a weight, an incomplete reading, a reading that doesn't match the mail's figures, or a lane moved without naming the airport → one question in the customer's language (no amount), then a person; a plain "yes" after that question → a person, never the old rate; a yes WITH a new weight gets the new quote first. "Also quote / also need / a new shipment" is never a change, even with "instead".
- `insurance.py`: `INSURANCE` (default on): "include cargo insurance in the all-in: goods value 22000 EUR, insured at 110 %, premium 0.40 %" → value × cover × rate (minimum premium, ‰, other currency via the price result's fx) added to every option's all-in in `backend.Backend.price` (breakdown line + `option.insurance`), one sentence without digits in the quote (gate 6b); an ask without value or rate → one question, no freight-only all-in. backend/booking.py adds `quote.insurance` back when it re-checks a fresh rate.
- `sanctions.py`: `SANCTIONS`: Russia, Belarus, Iran, North Korea, Syria, Crimea/Donetsk/Luhansk as destination (code, city, or "final destination …") → fixed polite decline, no price.
- Also in this round (switches, default on): `RATEDESK` (portal 503 → ask ratedesk@ once after the bid cut-off, re-price), `CURRENCIES` (bids in £, zł, R$, SEK, "1 234,50" …), `MORE_CURRENCIES` (quote in PLN/SEK/CAD/JPY … via backend/data/fx_eur.csv), `AIRLINE_UPDATES` (offload/delay/rebooking mails → CRM + customer note), `FOREIGN_PICKUP` (AT/CH/NL/BE/LU/DK/CZ and out-of-zone German postcodes → nearest zone), `STATUS_LANGS`, `RELATIVE_DEADLINE`, `BID_NEUTRAL_FILES` (bid in documents.zip behind "see attached").
- `test_rfq_shape_sweep.py`: adversarial sweep of those shapes through the real RFQ path (own keyless backend on `NEXT_TRAPS_PORT`+1000).
- `postmortem.py <session> [--mail <5U id>]`: runs the gate on a sent quote (no LLM, sends nothing) to find the missing rule after a reject.
- `evals/traps.json` + `test_traps.py`: every rejected live round and expected trap through the whole RFQ pipeline. A new reject → add a case first.

## Rules
- Every LLM call goes through `llm.chat_json`. A new model needs its price in `llm.PRICES`.
- Budget: one tiny gateway call per RFQ (no call = no cost points; big calls eat the 40 cost points).
- Data shapes sent to the backend must match docs/CONTRACT.md (proposal: docs/PLAN.md §7).
- Never send a customer anything before the quote: the first reply in a thread is the one that counts.
