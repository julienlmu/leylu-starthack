# links: an RFQ's links are read like attachments, unsafe sites never opened, no popups
- Who: Julien (tool: Claude Code)
- Branch: julien/links
- What changed:
  - Links in an RFQ (a packing list on a server, a Google Drive/Docs or Dropbox share, a web page with the shipment data) are read like attachments: totals, DG and constraints see them. Share pages are turned into their download link.
  - **Safety:** only http/https on the default port. Never opened: user:password@ tricks, bare IP addresses, punycode look-alike names, hosts that resolve to localhost/LAN/cloud metadata. Every redirect is checked again (max 4). Only documents are read (PDF, Office, CSV/TXT, HTML, ZIP via the safe archive reader); programs/scripts are refused by type and by name. 8 MB stream cap, 5 s per link, 3 links, 10 s in total. Login pages are never used, nothing is ever typed into a site, no cookies are kept.
  - **No popups:** no browser and no JavaScript, one plain GET per hop. A page's scripts, styles, frames, dialogs and popup/cookie/newsletter overlays are dropped with everything inside them before its text is read.
  - An unsafe or failing link is skipped and shown in the session ("Link … not opened: <reason>"); the quote goes on from the mail.
- Files touched: agent/links.py (new), agent/rfq_agent.py, agent/test_links.py, agent/conftest.py (tests never open real links)
- Contract/API changes: none
- New env vars / packages: LINK_READ=off disables it (httpx was already a dependency)
- How verified: make check green (agent 2108 passed, backend 231 passed, eslint+tsc); test_links.py runs offline (fake web + fake DNS): unsafe URLs, redirect into the LAN, .exe by type and by name, login page, 8 MB cap, popup/cookie/script page, share links, and a full handle_rfq where the DG sits behind the link
- Known issues / TODO: pages that need JavaScript to show their content (WeTransfer, OneDrive viewers) give no text → treated like an unreadable attachment. The host is resolved by us and again by httpx (a DNS-rebinding window, noted in the code).
- Heads-up for teammates: an RFQ with links can take up to 10 s longer before the bid requests go out.
