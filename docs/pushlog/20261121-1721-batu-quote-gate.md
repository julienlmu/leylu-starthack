# quote-gate: one last free check before every quote, a dead man's switch for held quotes, and a trap suite
- Who: Batu (tool: Claude Code)
- Branch: batu/quote-gate
- What changed:
  - agent/gate.py (new, no LLM): runs on every priced RFQ before the mail goes out. fix = we change the quote ourselves, hold = a person should look, note = log only. Rules: DG the other checks miss (UN numbers, dry ice, corrosive, gas cylinders, radioactive, …) → the template's DG paragraph; temperature-controlled, perishable, valuables, non-stackable → one sentence the customer expects (never with digits: one amount per mail); a piece over the lower deck (taller than 160 cm, longer than 300 cm, heavier than 1500 kg) → freighter sentence; live animals / human remains → hold; "must arrive by <date>" and "budget EUR x" narrow the options before the pick (only when the backend's choice breaks the constraint); fastest asked but a faster option exists → fix (never on bids-only lanes, those stay 50/50); door-to-port without a pickup leg (round 1 too_low) and a total below half the median → hold; price in USD/CHF/GBP asked → hold; prompt injection → note; the written mail must state exactly one amount, its currency and, for DG, the papers. /api/price "warnings" (PR #64) are logged as notes
  - Dead man's switch: a held quote flags the session (needs_human → ntfy via the backend) and goes out on its own at GATE_AUTO_SEND_SECONDS (240 s after the RFQ) unless a person pauses or quotes by hand. No answer scores 0, a late quote still scores accuracy + cost. GATE_MODE=warn logs the same findings but changes nothing; off disables it. The gate fails open: an exception logs an error and the plain quote goes out
  - Corrections before the quote: a customer mail in the thread while the session is new/pricing is parked (agent/amendments.py); the RFQ agent reads the request again with it on top (one more extraction, only then) and prices again, so the one quote that counts uses the corrected figures. Before: hand-over, and the RFQ agent quoted the old figures
  - "OK, book it, but change the pickup to the 30th" is no longer a rule-based yes (booking_agent CHANGE words → LLM intent → question → person)
  - agent/test_traps.py + agent/evals/traps.json: rounds 1 and 10 (real mail text, real PL_53839.xlsx) and 15 expected traps run through the whole handle_rfq pipeline (extraction mocked, nothing sent). With GATE_MODE=off 10 of them fail. agent/postmortem.py runs the gate on a stored session (no LLM, read-only GETs) after a reject
