# memo-wins: a voice memo's figures win over the mail's (a correction in the memo was lost)
- Who: Batu (tool: Claude Code)
- Branch: batu/apple-speech (PR #186, second push)
- What changed:
  - Before: a memo's transcript only reached the extraction when the mail left origin, destination or weight open (`_read_attachments_too`); `attachment_totals` only reads "total gross weight". So "mail: 2 pallets, 400 kg / memo: sorry, it's 3 pallets, 640 kg" was priced at 400 kg (too_low)
  - Now `_memo_wins`: a transcript with cargo figures (`extract.CARGO_FACT`, or any 2+ digit number / 公斤) is read together with the mail (+ up to 2 other attachments), under a header telling the model the memo is the newer information and its figures win. One extra small call, only on an RFQ with a memo that has numbers; it replaces the attachment re-read (never both)
  - A memo read that fails, or comes back less complete than the mail's reading, keeps the mail's reading. Session event: "Voice memo read with the mail: 3 pcs, 640 kg, MUC to JFK (the mail alone: 2 pcs, 400 kg, …)"
  - `MEMO_WINS=off` + restart: the old path
- Files touched: agent/rfq_agent.py (`_memo_wins`, `heard` list from `_attachment_texts`), agent/test_media.py
- Contract/API changes: none
- New env vars / packages: `MEMO_WINS` (default on; only matters with MEDIA_READ=on)
- How verified: agent pytest 1690 passed, 17 xfailed (on main 3ea6048); test_media 34 (new: correction in the memo reaches the price, cost = mail read + memo read; no numbers → no extra call; switched off → old path; memo-only RFQ read once more, not twice; failed memo read keeps the mail's reading). No live call
- Known issues / TODO: an amendment mail arriving before the quote re-reads the request without the memo (amendments.py)
