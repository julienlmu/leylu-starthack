# PR248-fix: pasted portal rates locked down and fitted into the one portal-down flow
- Who: Julien (tool: Claude Code)
- Branch: julien/pr248-fix
- What changed:
  - SECURITY: `POST /api/sessions/{id}/portal-rate` was an open write endpoint behind the public Next proxy (anyone could inject a fake rate that gets quoted and booked). Now it needs header `X-Paste-Secret` = `PORTAL_PASTE_SECRET` (hmac.compare_digest; unset = endpoint off, 403) and checks lane (must equal the session's), airline (known portal code only), EUR/USD, total (> 0, ≤ 100k, 0.3–50 per chargeable kg), transit (0–30 d), rate ID shape, text ≤ 5000 chars, session not quoted yet. Every paste (accepted, repeated, refused) is logged on the session.
  - Userscript: asks the secret once and keeps it in Tampermonkey storage (no key in the file), sends origin/destination, only posts to localhost/127.0.0.1 (a crafted `#b=` link can't steal the secret).
  - Flow: a rate typed during the rate desk wait is now priced even when the desk also answered (was stored but left out of the quoted price); PATCH `bids` keeps pasted `manual_portal` bids (agent writes can't overwrite a paste); a live portal answer for an airline drops typed / `portal_web` rates for it (live API > web page / person > nothing). One alert per RFQ stays as in #248 (`_PROBED`).
- Files touched: backend/app.py, backend/portal_paste.py, backend/pricing.py, backend/test_portal_memory.py, agent/rfq_agent.py, agent/portal_helper.user.js, agent/test_portal_probe.py, agent/AGENTS.md
- Contract/API changes: portal-rate needs `X-Paste-Secret` and `origin`/`destination` in the body; pasted bids carry `airline_code`; PATCH `bids` keeps `manual_portal` bids. (The endpoint is not in docs/CONTRACT.md yet.)
- New env vars / packages: `PORTAL_PASTE_SECRET` (backend; unset = paste endpoint off)
- How verified: make check green (NEXT_TRAPS_PORT=9021); new tests for secret/validation/logging, PATCH keeping a paste, live-wins pricing, desk+typed pricing (fails without the fix)
- Known issues / TODO: PATCH /api/sessions/{id} and the other write endpoints are still open through the public proxy (pre-existing, not part of #248)
- Heads-up for teammates: set `PORTAL_PASTE_SECRET` in the live backend's .env before using the userscript, and enter it once in Tampermonkey.
