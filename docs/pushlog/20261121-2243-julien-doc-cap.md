# doc-cap: a DG line past the 20,000-character cap is no longer lost (zips / forwarded mails with several documents)
- Who: Julien (tool: Claude Code)
- Branch: julien/doc-cap
- What changed:
  - /api/attachments/text kept only the first 20,000 characters. With #166/#168 a zip or an .eml brings several documents in one attachment; measured: a zip with a tariff then the packing list puts the UN3480 line at ~44,800 characters, so the DG check never saw it
  - Now: the first 20,000 characters as before, plus every later line with a DG/weight signal (UN number, class, dangerous/Gefahr, lithium, MSDS/SDS, kg, gross/brutto, total, pallets, cbm), at most 10,000 more. The LLM re-read still takes 2,500 characters per attachment (cost unchanged)
  - Measured worst cases: 5 MB unknown binary 0.27 s, 8.6 MB data file 0.24 s, 20-file zip and 3-level nesting instant (caps hold)
- Files touched: backend/app.py, backend/test_doctext.py
- Contract/API changes: none (same field, more of the right text)
- New env vars / packages: none
- How verified: make check green; new endpoint test: the zip above returns the UN3480 line (< 31,000 chars), and .odt/.eml/.rtf through the real endpoint
